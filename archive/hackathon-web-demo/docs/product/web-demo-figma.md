## 交互及实现注意

- 正常原型：开启摄像头 → 开始录制 → 结束 → 预览 → 提交 → 上传 → 排队 → 识别 → 结果。录制页也配置了 10 秒自动进入预览。
- 原型中的上传、排队、识别分别使用 1.2 秒、2 秒、2 秒定时过渡，只用于演示状态变化，不能作为真实性能数据。
- 复制按钮进入“已复制”反馈页，1.5 秒后返回；原型不会实际写入系统剪贴板。
- 点击清空 → 确认后进入空记录页面；取消返回结果。上传、等待、处理中的清空按钮禁用。
- 服务离线、模型未就绪时禁止提交。容量满时保留当前页面内的视频，容量恢复后才解禁手动提交；容量拒绝不等于重新运行模型。
- 识别失败只提供重新录制。上传中断、视频无效、任务超时及结果过期等其他错误，开发时复用任务面板并按 PRD 显示具体原因；目前未逐一绘制独立页面。
- 正式实现必须保留多次录制之间的本机历史，并恢复尚有效的未完成任务。Figma 的导航及示例记录不模拟真实存储；“再录一句”仅返回录制入口。
- 容量示例按首轮候选配置展示：识别并发 1，上传中与等待中合计上限 10。最终参数以 PRD 及实测为准。
- 视频、凭证及文本的清理时点以 PRD 为准；“清空本机识别记录”只清理当前浏览器应用记录，不影响其他观众。
- 页面仅保留必要的用途、删除规则、错误原因和实验模型提示；开发说明位于 Figma 画布外侧。
