### 2026-10-10：Prototype v0.1 先做固定视频识别

- **决策**：第一版只实现“选择固定无声视频 → 中文唇语识别 → 显示文字结果”。
- **明确不做**：实时摄像头、Alt 快捷键、输入框自动填充、系统级输入法和 AI 改写。
- **原因**：先单独验证最核心的中文视觉语音识别链路，避免把模型、摄像头采集、快捷键和文本注入等多个风险混在一次实验里。
- **测试材料**：User 0 录制 5 段、每段不超过约 10 秒的普通话视频，并为每段保留标准答案。
- **验收边界**：P0 只证明能够完成推理、输出文字并记录结果；不据此宣称真实场景可用或模型达到稳定的 80% 准确率。
- **下一步**：录制测试视频，确定标准答案，运行第一次固定视频识别实验。

### 2026-10-11：完成 CNVSRC2025 固定视频基线冒烟测试

- 类型：实验 / 结果 / 失败边界
- 问题：不接入实时摄像头和系统级输入法时，公开中文视觉语音识别模型能否在本机完成“视频 → 嘴部序列 → 中文文本”的最小链路？
- 可观察输入与条件：`test-videos/2/1-1.mp4`；131 帧；1920×1080 画面；30 FPS；单人正面手机视频；视频已静音。
- 我的决策或工作：选择 CNVSRC2025 baseline；将检测输入缩放到最长边 960 像素以适配 CPU；使用官方 RetinaFace/FAN 预处理组件生成 96×96 嘴部视频，并补充真正的 30 FPS→25 FPS 时间重采样；保留原始视频和可复查的预处理结果。
- AI / 上游资源协助：AI 协助搭建依赖环境、定位 Windows 路径与 CPU 兼容问题、编写 `scripts/cnvsrc_prepare_single_video.py` 和推理命令；CNVSRC2025 提供模型结构、预处理组件和权重。
- 结果：人脸/关键点预处理成功，检测到 `131/131` 帧。初始版本把 131 帧直接标成 25 FPS，输出 CER 为 `52.94%`；MobileNet + 真正重采样为 `109` 帧后，同一权重输出 `你好我想用说剧组和人工智能聊天`，CER 降为 `29.41%`。ResNet50 + 同样的真重采样输出回到 `你好我想用说剧组和成功社的聊天`，CER 为 `52.94%`。
- 证据位置：`scripts/cnvsrc_prepare_single_video.py`；`test-results/cnvsrc2025/1-1-lips-960-mobile-resampled.mp4`；`test-results/cnvsrc2025/prediction-groundtruth-resampled.json`；`test-results/cnvsrc2025/1-1-lips-960-resnet50-resampled.mp4`；`test-results/cnvsrc2025/prediction-groundtruth-resnet50.json`；模型权重位于外部 CNVSRC2025 仓库的 `VSR/pretrained_models/model_avg_cncvs_2_3_cnvsrc.pth`。
- 结论：技术链路已通过；初始 52.94% 结果不能直接用于评价模型，因为包含时间轴错误。修正后 MobileNet 版本能够识别句子的部分结构，但仍将关键短语“唇语输入法”识别成“说剧组”；ResNet50 对照没有改善，反而回到 52.94%。当前最佳结果仍未达到可用中文唇语输入标准，但这组 A/B 说明预处理和人脸对齐会显著影响结果，不能简单归因于模型权重本身。
- 编码补充：官方 `predict.py` 使用未指定编码的 `open(infer_path, 'w')`。Windows 默认环境下生成的 `prediction.json` 为 GBK；本次用 Python UTF-8 模式重新生成 `prediction-utf8.json`，避免把编码问题误判成模型乱码。
- 未验证项：中文句子级准确率、不同语速稳定性、五段视频的一致性、推理延迟是否适合实时摄像头、上游权重和数据的再分发许可。
- 下一步：先用官方样例或数据集样例做管线对照；再对其余固定视频完成同口径评估。如果官方样例正常而用户视频失败，优先调查拍摄域差异；如果官方样例也失败，再调查模型权重、预处理版本或更换模型。

### 2026-10-11：完成新闻播音员基准测试并暂时归档

- 类型：实验 / 结果 / 决策
- 问题：标准普通话新闻播音员、稳定正面机位的视频，能否让当前中文视觉语音模型达到可用识别效果？
- 可观察输入与条件：`test-videos/3/` 下 5 段视频；1920×1080；30 FPS；单人正面画面；3 条长句、2 条短句；标准答案记录在 `docs/line.md`。
- 我的决策或工作：停止继续扩展当前模型测试；使用与本人视频完全相同的 CNVSRC2025 MobileNet 人脸检测、FAN 关键点、96×96 嘴部裁剪和真实 30→25 FPS 重采样流程，建立新闻播音员外部基准。
- AI / 上游资源协助：AI 协助复用已验证的预处理脚本、补齐 5 段标签 CSV、运行 CPU 推理并整理 CER；CNVSRC2025 提供推理代码、模型结构和权重。
- 结果：5 段视频均完成全帧人脸/关键点检测；总编辑错误 `87/170`，总 CER `51.18%`。三条长句为 `74/150 = 49.33%`，两条短句为 `13/20 = 65.00%`。嘴部裁剪位置正常，未发现明显预处理失败。
- 证据位置：`test-results/cnvsrc2025/news-reference/result-summary.md`；`test-results/cnvsrc2025/news-reference/groundtruth.csv`；`test-results/cnvsrc2025/news-reference/prediction.json`；5 个 `*-lips-960-mobile-resampled.mp4`；`docs/line.md`。
- 结论：新闻播音员素材也未达到可用中文唇语输入标准；当前问题不能仅归因于用户发音或自拍视频质量。继续测试同一模型的边际收益较低，暂时归档更合理。
- 未验证项：未来新中文模型、个人适配训练和实时摄像头输入仍未验证；本次结论不代表中文唇语识别研究已经没有突破空间。
- 下一步：暂停当前项目的主动开发和模型测试；保留仓库与证据，待新的中文模型或明显更强的公开基线出现后，从本节结果继续比较。

### 2026-10-11：从固定视频 Prototype 转入实时 MVP

- 类型：决策 / 实现 / 待验证
- 问题：固定视频技术链路虽然已经跑通，但用户仍然需要手机录制、导出或传输视频，再手动执行识别；这没有验证“在电脑前直接完成一次无声输入”的产品闭环。
- 可观察输入与条件：User 0 明确把“按 hotkey 控制摄像头，完成一次唇语识别并得到文本”列为当前最高优先级；准确率可以继续优化，但不再作为实现实时交互的前置条件。
- 我的决策或工作：把 MVP v0.1 收敛为“启动介绍页（摄像头关闭）→ 按住 Right Ctrl 启动摄像头并录制 → 松开关闭摄像头 → CNVSRC2025 最终识别 → 复制到剪贴板”，暂不做系统级输入法、自动粘贴、音频和 LLM 润色。
- AI / 上游资源协助：AI 根据已验证的 CNVSRC2025 预处理和权重，新增 `scripts/lip_input_mvp.py`、启动脚本和 `docs/mvp-prd.md`；CNVSRC2025 提供模型、权重、RetinaFace/FAN 预处理和解码组件。
- 结果：模型自检已通过，确认代码能够加载 CNVSRC2025 权重并初始化实时识别所需组件；真实摄像头录制、快捷键事件、最终识别耗时和剪贴板结果尚未完成验收。
- 证据位置：`scripts/lip_input_mvp.py`；`scripts/run_lip_input_mvp.ps1`；`docs/mvp-prd.md`；本条记录；运行时生成的 `outputs/mvp/recognitions.jsonl`。
- 结论：当前可以诚实地说“实时 MVP 已进入实现并通过模型自检”，还不能说“唇语输入法已经可用”或“准确率已经解决”。
- 未验证项：摄像头在用户实际姿态下是否稳定检测；Right Ctrl 按下/松开是否符合预期；CPU 端实时反馈延迟；最终识别是否能复制到剪贴板；连续使用时的失败率。
- 下一步：启动 MVP，完成至少 3 次真实录制；记录每次是否成功、帧数、最终耗时、输出文本和失败原因，再决定先优化交互还是先优化预处理/模型。

## 5. AI 协作记录规则

每次让 AI 实现功能前，我先写清楚：

1. 用户要完成什么任务。
2. 这次只解决哪个问题。
3. 输入、输出和限制是什么。
4. 什么情况算完成。
5. 哪些方案不接受，为什么。

AI 可以生成代码、测试、文档和候选方案，但不能替我默默决定用户、范围、优先级和验收结果。

## 6. 当前不能使用的强表述

- “训练了中文唇语模型”：目前只是计划复用公开模型。
- “完成了中文唇语输入法”：目前没有本机和用户验收证据。
- “验证了市场需求”：目前只有 User 0 的问题假设。
- “独立完成全部工程”：如果代码主要由 AI 生成，应准确说明自己的产品决策、适配、测试和迭代贡献。
