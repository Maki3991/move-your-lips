## 1. 背景与问题

项目需要为黑客松评委和观众提供一个可以打开并实际体验的在线 Demo。当前产品是桌面程序，模型和识别流程依赖本地环境；轻量 VPS 不适合直接承载现有唇语识别模型。因此采用分离式方案：VPS 提供网页和任务协调服务，项目发起人的笔记本运行模型并主动连接 VPS 领取任务。

观众以自己的手机访问网页，使用前置摄像头录制无声视频并提交。识别完成后，结果返回发起提交的同一手机网页。用户无需注册或提供真实姓名。

## 2. 产品目标

1. 评委或观众通过公开 HTTPS 网址，在手机浏览器完成一次真实的录制、提交、排队、识别和结果查看流程。
2. 浏览器明确显示模型后端是在线、准备中、繁忙或离线；离线或未就绪时不能提交新任务。
3. VPS 为每次提交创建独立任务，使上传视频、状态和文字结果只返回给对应提交者。
4. 对上传、排队和推理资源设上限；容量不足时拒绝新任务并说明原因。
5. 临时视频和文字按明确规则自动清理；发起人的笔记本不积累观众的识别历史。
6. 观众可以主动清除当前浏览器保存的任务编号和识别记录。

## 3. 非目标与产品边界

- 不迁移或归档现有桌面程序，不重写桌面版；网页功能作为新部分加入仓库。
- 不在 VPS 上运行或训练唇语识别模型。
- 不做账号注册、实名识别、长期云端历史、社交分享或评委统一管理面板。
- 首版不提供重新识别/任务重试流程；提交后的暂时性失败需要用户重新录制并重新提交。
- 不申请麦克风权限、不录制或上传音频、不调用大语言模型改写识别文字。
- 不承诺中文唇语识别准确率；现有实验表明整句识别仍不稳定，Demo 应呈现模型原始结果和失败状态，不把可运行误称为准确。
- 首版以手机系统浏览器为目标；微信内置浏览器单独验证，不作为首轮可用性的前提。

## 4. 用户与核心流程

### 4.1 参与者

- **观众**：用自己的手机录制并提交视频，查看其对应的排队状态和识别文字，必要时清理本机记录。
- **笔记本 Worker**：项目发起人本机运行的后台程序，主动连接 VPS、领取视频、预处理和运行模型，然后回传结果。
- **VPS 服务**：提供网页、任务 API、有限队列、临时文件和结果交接。

### 4.2 正常任务生命周期

```text
观众打开 HTTPS 网页
  → 查询服务在线与模型就绪状态
  → 同意使用前置摄像头
  → 录制无声短视频并预览/重录
  → 请求任务名额，取得随机任务编号及查询凭证
  → 上传视频到 VPS；上传和验证成功后手机释放视频内存
  → VPS 校验视频并按规则排队
  → 笔记本 Worker 主动领取任务并下载视频
  → 本机解码、检测人脸/嘴部、裁剪和调整输入帧
  → 调用现有中文唇语模型
  → Worker 将识别文字和任务编号回传 VPS
  → VPS 确认持久化结果并删除该任务视频
  → Worker 收到 VPS 确认后删除本地视频和中间文件
  → 原手机网页查询并显示对应结果，保存文字记录
  → 手机确认结果已保存后，VPS 删除暂存文字与任务凭证
```

任务状态至少包括：`uploading`、`queued`、`processing`、`succeeded`、`failed`、`expired`。容量拒绝是提交响应，不创建可运行任务。

### 4.3 返回观众的结果

结果必须返回到提交该视频的浏览器，而不是只显示在发起人的电脑上。每个任务使用不可预测的随机 ID 和随机查询凭证关联。服务端校验查询凭证，不依赖姓名，也不能允许只凭连续递增或可猜的任务编号读取他人结果。

同一浏览器首版可允许多条分别编号的任务；界面和存储按任务逐条关联。重复提交请求应使用同一个客户端提交幂等标识，避免网络响应丢失时创建重复任务。首版不支持任务重新推理。

## 5. 手机网页体验

1. 页面加载后显示模型服务状态和当前负载。
2. 用户主动点击开启摄像头；浏览器请求前置摄像头权限，拒绝权限时给出可恢复的说明。
3. 提供取景预览、录制计时、停止和重录。限制录制时长、分辨率与文件大小；建议初始测试 5–10 秒、480p/640×480、无音频，但应以嘴部清晰度与实测上传体验决定最终值。
4. 上传期间显示进度；提交后显示任务状态和等待信息。
5. 正常结果显示模型原始文字与复制操作；空输出、识别失败和识别内容不准确彼此区分。不得把识别错误伪装成传输错误。
6. 用户刷新或短暂离开后，可用本机保存的查询凭证恢复未完成任务；清除浏览器数据或更换设备后不保证恢复。
7. 说明上传完整脸部视频用于本次嘴部定位和唇语识别，以及临时数据的清理规则。用户确认摄像头权限本身不替代这项用途说明。

## 6. 后端状态与名额

### 6.1 在线状态

Worker 定期向 VPS 发心跳，并报告模型是否已加载。页面显示：

- **准备中**：Worker 已连接，但模型尚未就绪。
- **Online**：Worker 在线且模型就绪，可以申请上传名额。
- **繁忙**：Worker 在线但处理资源已占用；仍可以按已配置的排队容量提交。
- **Offline**：超过心跳超时窗口没有健康信号；拒绝新提交。

初始可将心跳离线判定窗口设为约 20 秒，作为待验证配置。网页展示的在线状态可能有短暂延迟，创建任务时服务端必须重新校验。

### 6.2 初始容量候选值

以下是用于首轮实现与压测的候选配置，不是已完成的性能结论：

| 资源 | 首轮候选 | 规则 |
| --- | ---: | --- |
| 并行上传 | 2 | 同时接收的上传任务不超过 2 |
| 上传中 + 等待中的任务 | 最多 10 | 上传中的任务也占队列容量，避免绕过排队限制；满额时拒绝新任务 |
| 同时处理 | 1 | 笔记本先按单任务识别实现和实测；是否提升到 2 或 3 由总吞吐、单任务延迟、内存与错误率共同决定 |

处理中的任务不占等待队列容量，但占处理名额。并行上传是子上限，受“上传中 + 等待中最多 10 条”的总上限约束。识别名额包含视频下载、解码、嘴部检测/裁剪及模型推理，避免预处理工作绕过并发限制。

队列容量只限制任务数还不够。首轮候选单视频上限 10 MB、VPS 视频临时目录总额度 200 MB；提交前预留容量，上传中断和过期任务及时回收。数字需结合 VPS 实际剩余磁盘、3 Mbps 左右带宽及浏览器录制文件实测调整。结果库、日志另设大小上限并定期清理。

## 7. 数据存储与生命周期

### 7.1 数据分类

| 数据 | 观众手机 | VPS | 发起人笔记本 |
| --- | --- | --- | --- |
| 录制中的完整脸部视频 | 仅浏览器内存中的 Blob | 上传成功后临时磁盘文件 | Worker 领取期间的临时文件 |
| 嘴部裁剪/中间数据 | 不保存 | 不保存 | 仅内存处理，必要的临时文件在任务结束后删除 |
| 任务 ID、查询凭证 | `localStorage` 小型记录 | 任务索引和凭证校验信息 | 不持久保存 |
| 识别文字、完成时间 | 结果送达后保存到浏览器 `localStorage` | 为结果交接临时保存 | 不写入桌面历史或长期日志 |
| 模型权重、程序与运行环境 | 无 | 无 | 长期本地保存 |

### 7.2 删除规则

- **观众手机视频**：只在网页内存，不写入相册或 `localStorage`。收到 VPS 上传完成确认后释放 Blob，并停止/释放摄像头。若上传尚未确认，不宣称上传成功；页面关闭时内存会随页面销毁。
- **VPS 视频**：排队与处理期间保留。Worker 回传识别文字且 VPS 确认结果已保存后，立即删除原始视频；失败、超时、取消和孤儿文件也执行清理。
- **笔记本视频**：Worker 下载和处理期间暂存。VPS 确认收到识别结果后删除视频及本地中间文件。Worker 启动时清理过期残留。笔记本不记录观众的长期识别历史。
- **VPS 文字结果**：等待原手机取得并确认已保存后，VPS 删除文字及查询凭证。交接失败时最多暂存 1 小时，之后自动过期删除；正常确认无需等满 1 小时。
- **排队视频**：Worker 离线时只在有限容量下暂存；候选等待过期时间 30 分钟。到期标记失败、删视频并归还名额。
- **手机本地文字记录**：保存编号、结果、时间和过期元数据，默认由用户主动清除；可以设置记录保留时长，但在产品确认前不自动清空有效本机记录。

自动清理必须覆盖正常完成、失败、超时、上传中断、进程重启和数据库中过期任务。清理应用文件不等同于对磁盘做取证级安全擦除。

### 7.3 清空本机识别记录

页面提供“**清空本机识别记录**”操作，适合观众在离开共享设备前主动使用。点击后先确认，再删除当前浏览器中本应用保存的全部任务编号、查询凭证、识别文字和历史展示数据，并清空界面。

该功能只清理当前浏览器/设备的本地记录，不会清理 VPS 上尚在处理或等待交接的任务，也不会声称删除其他用户的数据。界面需说明服务端临时数据仍按自动过期规则清理。

在仍有未完成任务时，首版候选行为是禁用清空按钮并提示任务完成后再清理，避免用户失去查询凭证；若后续希望支持边等待边清理，需要另行定义服务端取消语义。

## 8. 异常与恢复行为

| 异常 | 用户可见行为 | 服务端/Worker 行为 |
| --- | --- | --- |
| Worker 离线或模型未加载 | 显示 Offline/准备中，禁用新提交 | 保留已接收任务至等待期限；超时后结束并清理 |
| 摄像头权限拒绝或不可用 | 说明如何在浏览器设置中允许权限或释放摄像头 | 不创建任务 |
| 视频格式、时长、大小无效 | 显示具体原因，允许重录 | 拒绝并删除未完成上传临时文件 |
| 网络上传中断 | 显示上传失败，原录制可在当前页面内存仍存在时重试上传 | 删除不完整文件并释放预留容量；无识别任务重试 |
| 队列满/磁盘额度满 | 说明当前不能提交，建议稍后重试 | 原子检查容量后拒绝新任务，不保存完整视频 |
| 视频中无法定位清晰嘴部 | 提示正对镜头、改善光线并重新录制 | 标记失败，删除 VPS/Worker 临时文件并释放处理槽位 |
| 模型异常/处理超时 | 显示本次识别失败 | 终止或隔离卡住的工作，标记失败并清理；由用户重新录制提交 |
| 电脑回传成功但网页暂时断线 | 页面恢复后仍可查询暂存结果 | VPS 暂存最多 1 小时；收到客户端确认后立即清除 |
| VPS/Worker 重启 | 任务恢复或明确失败，不可永久停在处理中 | 启动清理孤儿文件；给任务设置租约和超时，拒绝迟到结果覆盖终态 |
| 模型返回不准确文字 | 明确标为识别结果，可复制或重新录制 | 这是成功推理而非系统错误，不自动重试 |

同一任务完成、失败或过期后只能进入一个终态。过期 Worker 结果不得覆盖终态；重复回传同一结果应幂等处理。

## 9. 初步系统边界

首版逻辑组件建议为：

- `web/`：手机网页、录制预览、任务状态和本地记录清理交互。
- VPS 上的 Web/API 服务：静态页面与 HTTPS API、容量控制、任务索引、临时视频与结果交接、清理任务。
- 笔记本 Worker：主动发起受认证的连接/轮询领取任务，下载、预处理、调用项目识别器、回传文字并清理本地临时文件。
- 现有 `scripts/`、模型和桌面 UI 保留。复用识别与预处理代码时应隔离桌面 UI 依赖，并验证权重、路径、依赖和许可证；不为本 Demo 迁移整个现有程序。

具体 Web 框架、消息传输方式、部署目录、域名、证书和进程管理尚未定案。Worker 应主动连接 VPS，避免要求笔记本有公网 IP 或开放入站端口。VPS 作为上传暂存与任务协调中转，移动网络与笔记本无需处于同一 Wi-Fi。

## 10. 安全、隐私与滥用控制

- 公网页面使用 HTTPS；浏览器仅在用户操作后请求摄像头权限，不请求音频。
- 页面提交前说明上传的是完整脸部视频、用途为本次识别及对应的自动删除规则。
- 文件按随机任务 ID 命名，不信任客户端文件名；校验类型、大小、时长，并避免可执行内容和路径注入。
- Worker 使用单独的高强度凭证/密钥连接 VPS，不将其暴露给浏览器；Worker 仅领取授权任务。
- 查询凭证使用高熵随机值，浏览器对外只请求自己的任务；敏感 token 不写入访问日志。
- 实施请求速率、并行上传、排队数、文件大小和总磁盘配额限制，提供清理和基础运行日志。
- 日志只保留任务 ID 的安全短标识、时间、状态、耗时和错误类别；不记录原始视频、查询 token 或识别文字。
- 依赖和模型授权需在公开 Demo 前复核。当前仓库已注明 CNVSRC2025 VSR 有非商业比较/基准用途限制；黑客松公开演示的许可适用性需要确认。

## 11. 验收标准

### 功能验收

1. iPhone Safari 与至少一种 Android 系统浏览器可以通过 HTTPS 打开页面、授权前置摄像头、录制、预览并上传无音频短视频。
2. 页面准确显示 Worker 离线、模型准备中、在线、处理与排队状态；服务端状态检查能够阻止离线时的新任务。
3. 上传、队列和处理中各任务数始终不超过配置上限；并发提交不会突破容量限制；满载和磁盘额度不足时明确拒绝。
4. 至少两个浏览器并行提交时，每个页面只能查询和收到自己任务的状态与文字结果。
5. 成功处理能由本地模型完成脸部/嘴部预处理并生成原始文字；无法检测、模型失败与超时能返回明确终态。
6. 上传确认后手机释放视频内存；VPS 在成功结果持久化后删除视频；Worker 在收到结果确认后清除本地临时文件；结果确认交接后服务端删除文字。
7. 手机刷新后可用任务凭证恢复有效任务；点击“清空本机识别记录”并确认后，本地编号、凭证、文字与界面记录均清除，服务端临时数据按既定规则独立过期。
8. 服务/Worker 重启及异常退出后，孤儿视频最终被清理；任务不会无限期卡在处理中，空间不足不会继续收取视频。

### 演示可靠性

- 在目标网络条件下连续完成至少 10 条端到端录制与识别任务，记录成功/失败、上传时间、等待时间、推理时间、文件大小、CPU/内存峰值及模型输出。
- 使用多个手机/浏览器做隔离验证，并测试队满、Worker 离线、上传中断、摄像头拒绝、无脸/无嘴部帧、超时和 VPS 磁盘额度不足。
- 只有性能测试证明吞吐收益且内存留有安全余量后，才把同时处理从 1 提升到 2 或 3；否则保持 1 并如实展示排队状态。
- 模型结果质量与基础设施可用性分别记录；端到端成功不代表识别内容准确。

## 12. 决策记录与待确认项

### 本轮已明确的产品方向

- 在线演示由 VPS 提供网页和轻量协调，笔记本运行模型；不把当前整个桌面项目搬到新目录，网页版作为独立新增部分。
- 从 `web/` 开始新增网页代码；服务与 Worker 的物理目录可以随实现调整，现阶段不冻结最终工程结构。
- 观众用自己的手机和前置摄像头；摄像头需用户同意，公开网页采用 HTTPS。
- 手机录制完整脸部无声视频，后端自动检测并裁剪嘴部；观众不需手工裁剪。首版暂按笔记本端处理，避免手机部署另一套检测模型。
- 结果一对一回到提交视频的手机页面；不用姓名/账号，使用随机任务 ID 和私密查询凭证关联。
- 手机视频在收到 VPS 上传成功确认后释放；VPS 和笔记本视频在完成相应交接后立即删，不为视频保留一小时或设计识别重试。
- 识别文字不保存在项目发起人的笔记本长期历史里。VPS 只在向手机交接时暂存文字：手机确认保存后立即删除；未确认时最多保存 1 小时后删除。
- 观众可在当前浏览器保存编号与文字结果，并有“清空本机识别记录”入口；该入口只清理当前浏览器数据。

### 尚待实测或最终确认

- 上传并发 2、上传中+等待中总名额 10、首轮处理并发 1 是压测候选值；用户最初提出最多 3 条并发识别、10 条排队，实际识别并发应据笔记本实测确定。
- 单视频 10 MB、5–10 秒、480p/640×480、VPS 临时视频额度 200 MB、队列等待 30 分钟、结果交接最多 1 小时等均为初始建议值，不是已实测规格。
- 手机 `localStorage` 适合保存小型任务 ID、凭证和文字；浏览器清除站点数据、无痕模式、换设备会导致本地记录/任务恢复能力受限，最终交互需在目标浏览器验证。
- 上传失败时是否保留当前页面内存中的录制供重新上传；用户离开页面后是否提供取消任务；这些不构成模型重新识别重试功能，具体交互待开发前敲定。
- 清空按钮在任务未完成时禁用是首版候选行为；需确认失败/排队任务是否可先从本机清除，以及服务端任务如何继续至过期。
- VPS 当前运行状态、公网地址、磁盘剩余空间、开放端口、安全组、域名、HTTPS、实测带宽与进程管理方式均未验证。
- CNVSRC2025 权重与代码的许可是否涵盖本次公开黑客松 Demo，需复核第三方条款。
- 最终 Web 框架、任务存储实现、Worker 传输/认证方式和发布配置未定案。
