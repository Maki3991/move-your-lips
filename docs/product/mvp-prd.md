# 唇语输入法 MVP PRD

> 历史需求稿：记录 v0.2 和早期 v0.3 的设计想法。后续版本的实现范围见 `docs/product/prd-mvp-v0.3.md` 和 `docs/product/prd-mvp-v0.4.md`；下文状态保留撰写时的语境。

**版本**：MVP v0.2（当前实现）/ MVP v0.3（Home 记录管理设计稿）
**状态**：v0.2 已实现；v0.3 已完成需求设计，本轮尚未修改代码
**最后更新**：2026-10-12

**前置结论**：MVP v0.1 的实时交互闭环已经完成；识别准确率未通过可用性验收，因此本轮不把模型能力写成已解决问题。

## 1. 本次 MVP 要验证什么

本轮 MVP 0.2 不负责证明中文唇语识别已经足够准确，也不负责替换系统输入法。它有两个并行目标：

1. 把 MVP 0.1 的识别结果进一步接近真实输入场景：保留 Home 历史页，并增加用户主动开启的直接输入。
2. 对“识别准确率几乎为零”的反馈建立可复现的诊断基线，区分模型、预处理、实时采集和时间序列问题。

产品闭环仍然是：

> 用户在电脑前按住快捷键、无声地做出说话动作，松开快捷键后，系统能够完成一次中文唇语识别，并把结果复制到剪贴板。

固定视频 Prototype 已经证明“预处理 → 模型推理 → 中文文本输出”可以在本机运行；MVP v0.1 已把输入方式推进到“电脑摄像头 + 快捷键”。MVP v0.2 继续验证结果是否能安全进入当前输入框，同时对模型失败建立证据链。

## 2. 目标用户与场景

- **第一用户**：项目发起人本人。
- **核心场景**：教室、图书馆、办公室等不能或不方便出声、但用户仍坐在电脑前的场合。
- **拍摄约束**：单人、正面、稳定光线、嘴部无遮挡。
- **输出对象**：用户当前需要复制到其他应用中的中文文本。

## 3. MVP 用户流

```text
启动应用
  → 常驻后台进程 + Home 历史页（摄像头保持关闭）
  → 首次运行显示 setup / 模型加载 HUD
  → 按住 Right Ctrl
  → 启动摄像头并检测嘴部
  → 底部 HUD：嘴部关键点、LISTENING 和临时识别
  → 松开 Right Ctrl
  → 继续保留约 0.4 秒尾帧
  → 关闭摄像头
  → Reading your lips：完成最终识别
  → 结果显示并复制到剪贴板
  → 用户开启直接输入时，粘贴到当时的活动输入框
  → Home 历史记录刷新，Home 与 HUD 互不替换
```

## 4. In scope

- 启动后保持后台常驻，不自动打开摄像头，不创建大摄像头窗口。
- 首次运行显示 setup 引导和底部 loading/ready HUD；setup 当前不声称完成个性化模型训练。
- 按住 Right Ctrl 后才打开 Windows 摄像头。
- 使用已验证的 CNVSRC2025 中文视觉语音识别模型。
- RetinaFace/FAN 人脸与关键点检测。
- 裁剪嘴唇主体及少量周边，并固定显示在屏幕底部中央 HUD 的左侧。
- HUD 右侧上方显示 `LISTENING` / `READING YOUR LIPS`，下方显示实时识别效果。
- Right Ctrl 按下/松开控制一段输入。
- 松开 Right Ctrl 后默认继续采集约 0.4 秒尾帧，避免截断最后一个词的嘴型。
- 25 FPS 模型输入重采样。
- 识别状态显示：`READY`、`RECORDING`、`READING YOUR LIPS`。
- 识别结果复制到系统剪贴板。
- 本地记录识别文本、延迟和模型帧数。
- Home 页面显示本地历史记录，并在识别完成后自动刷新；文件发生变化时自动更新，也支持 `Ctrl+R` 手动刷新。
- Home 页面支持再次复制已有识别文本，并可打开本地存储文件夹；本轮不保存音频和原始视频。
- 提供显式开启的当前窗口粘贴模式；默认仍只复制到剪贴板。
- 建立固定测试集：至少 10 句话、每句话 3 次，保留标准答案和测试条件。
- 对同一批材料比较三条路径：固定视频离线识别、实时录制后离线识别、实时最终识别。
- 记录 CER、整句正确率、有效帧数、失败原因和耗时，作为后续换模型或个人适配的决策依据。

## 5. Out of scope

- 系统级输入法注册。
- 默认自动向任意输入框粘贴。
- 系统级输入法注册。
- 多人画面、侧脸、遮挡、拥挤环境和复杂光线。
- 麦克风、音视频融合或耳语模式。
- 外部 LLM 改写、总结和语义补全。
- 把个人微调或换模型承诺为必然有效的功能；它们只能作为受控实验。
- 保存音频、回放视频、重新转录和编辑历史记录。
- 识别准确率承诺或“可日常使用”结论。

## 7. 性能与质量边界

- 摄像头采集和嘴部框优先保持响应；实时文字预览默认约每 0.45 秒更新一次，允许延迟。
- CPU 推理下，松键后等待数秒属于预期，不把“实时”解释成逐帧即时识别。
- 松键后的 0.4 秒是采集尾帧，不代表模型在这段时间内已经完成识别。
- 最终识别沿用现有模型输出，不接入语义大模型，避免把模型能力和后处理能力混在一起。
- 识别准确率作为独立实验线记录；它不阻塞 UI 和直接输入开发，但模型候选不能只凭主观观感合并。
- CPU 主要影响推理耗时；只有在丢帧、有效帧不足或时间序列错误时，才可能间接影响准确率。
- 个人微调必须区分训练句和未见过的测试句，避免把记住训练材料误判为泛化能力。

## 8. 失败状态

- 摄像头打不开：提示检查 Windows 摄像头权限或切换摄像头编号。
- 没检测到人脸：提示正对摄像头并保持嘴部可见。
- 帧数过少：提示按住快捷键更久。
- 模型推理失败：保留错误类型，不复制空结果。
- 粘贴模式开启但活动窗口发生变化：显示明确提示，避免把结果写入错误窗口。
- 用户按 Esc：退出应用并释放摄像头。

## 9. 当前实现边界

MVP v0.2 延续隐藏根窗口、底部非抢焦点 HUD、后台摄像头线程和全局 Right Ctrl 监听，不做安装包、不做系统级输入法。Home 页面与 HUD 分离；代码保留实验性 `--paste` 入口，但默认仍只复制到剪贴板。setup 当前只完成使用引导，不代表个人化训练已经实现。

## 10. MVP v0.2 验收门槛

### 产品体验线

- Home 页面可以在 Right Ctrl 录制期间保持可见，HUD 不替换 Home。
- 识别完成后历史记录自动刷新，已有文本可以再次复制。
- 默认复制模式连续完成 5 次；显式开启粘贴模式后，在记事本中连续完成 5 次，且没有误粘贴到其他窗口。

### 模型诊断线

- 完成至少 10 句话 × 3 次的固定测试集，并保留标准答案。
- 报告固定视频、实时保存视频和实时最终识别三条路径的差异。
- 在没有证据前，不把换模型、个人微调或“24 句校准”写成已验证方案。
- 只有当候选模型或适配方案在未见测试句上改善 CER、整句正确率或有效输出率时，才进入下一版默认链路。

## 11. MVP v0.3：Home 记录与视觉素材管理（设计稿，未实现）

### 11.1 当前本地存储事实

当前应用使用追加写入的 `outputs/mvp/recognitions.jsonl` 保存识别日志，每行是一条独立 JSON 记录，现有字段包括：

- `at`：识别完成时间；
- `text`：最终识别文本；
- `latency_seconds`：最终推理耗时；
- `model_frames` / `capture_frames`：模型帧数和采集帧数；
- `checkpoint`、`face_model`、`device`：模型与运行环境；
- `output_action`、`ui`：输出方式和入口。

此外，`outputs/mvp/hud_setup_complete.json` 只表示首次使用引导是否完成。当前版本不保存麦克风音频、原始摄像头视频或可回放的嘴部视频，因此现有 Home 历史只能复制文本，不能播放素材或重新识别。

`recognitions.jsonl` 适合作为追加式运行日志和证据导出，不适合作为长期的用户管理数据库：它没有稳定的记录 ID，删除或更新单条记录需要重写整个文件，也没有记录与媒体素材之间的关联。

### 11.2 产品对象定义

v0.3 将一次识别拆成两个相互独立的对象：

1. **识别记录**：时间、文本、模型、耗时、帧数和转写版本。它是 Home 中一直保留的主体。
2. **视觉素材**：本次识别对应的无声口型视频和/或标准化嘴部帧。它用于预览和重新识别，可以被单独删除。

这里不使用“录音”作为产品术语：本应用默认不打开麦克风，不产生音频；“播放录音”应改成“预览口型片段”，“重新转写”应改成“重新识别”。

### 11.3 推荐的本地目录与数据层（技术方向，非用户体验验收）

建议 v0.3 不再让 JSONL 同时承担日志和 CRUD 管理职责，而是采用 SQLite 记录索引，加上独立的素材目录：

```text
outputs/mvp/
├── records.sqlite3          # Home 的记录索引和转写版本，应用的主数据源
├── records/                 # 每次识别一个稳定 ID 的素材目录
│   └── <record-id>/
│       ├── mouth.mp4        # 无声嘴部预览视频
│       └── input.npz        # 25 FPS、96×96 标准化嘴部帧，供重新识别
├── recognitions.jsonl       # 兼容现有证据日志，可继续追加或由数据库导出
└── hud_setup_complete.json  # 首次使用引导状态
```

第一版默认只保存嘴部裁剪素材，不保存完整人脸视频，以降低隐私风险和磁盘占用。`input.npz` 是为了让重新识别可以不重新打开摄像头、不依赖当时的人脸检测结果；当前模型接口接收完整帧、关键点和时间戳，因此接入它需要增加“从标准化嘴部帧直接推理”的入口。

### 11.4 Home 交互设计

每条历史记录在鼠标悬停时显示三个操作图标：

1. **复制**：复制当前记录显示的文本，不改变记录状态。
2. **删除记录**：二次确认后删除 Home 中的识别记录，并默认一并删除该记录的视觉素材，避免留下无法管理的孤儿文件。
3. **更多**：展开以下操作：
   - 预览口型片段；
   - 重新识别；
   - 查看详情；
   - 仅删除视觉素材。

“仅删除视觉素材”不会删除识别文本。删除后记录保留，并显示“素材已删除”；复制仍可用，但预览和重新识别应明确提示素材不存在，而不是静默失败。

### 11.5 重新识别与版本规则

- 重新识别不覆盖原始结果；每次重新识别都创建一个带时间、模型版本和预处理版本的新转写结果。
- Home 默认显示当前选中的结果，详情页可以查看同一素材的历次结果。
- 如果模型权重、预处理版本或 `input.npz` 缺失，重新识别进入明确失败状态，并保留原文本。
- 重新识别的结果可以再次复制，但不能把一次失败的重试静默替换成原始结果。

### 11.6 v0.3 功能分层

为了避免一次性把“素材保存、播放、数据库和模型重跑”混成一个大改动，按以下顺序实现：

**v0.3a：记录可管理**

- 为每次识别生成稳定 ID；
- 从 JSONL 迁移或导入旧记录；
- Home 卡片复制、删除记录、打开存储目录；
- 保存无声嘴部预览素材；
- 支持单独删除素材并保留文本记录。
- 将 Right Ctrl 改为“按一次开始、再按一次结束”；松开按键不再触发状态变化；
- 保留单次最多 20 秒的硬上限；用户第二次按键或达到上限后进入识别。

**v0.3b：素材可复用**

- 标准化嘴部帧持久化；
- 预览口型片段；
- 重新识别并保留转写版本；
- 详情页展示素材、模型和运行信息。

**v0.3c：直接输入（后续单独验收）**

- 记录开始时保存当时的目标输入窗口/输入位置；
- 识别完成后，目标仍然有效时直接输入结果；
- 目标窗口失去焦点、不可写或注入失败时，不把结果写入不确定的窗口；
- 直接输入失败不丢失记录，用户可以回到 Home 手动复制；
- 默认不主动覆盖系统剪贴板；“仅剪贴板输出”保留为显式备用模式。

### 11.7 单次输入与退出行为（v0.3 设计决定）

当前 v0.2 是按住 Right Ctrl 录制、松开后识别。v0.3 改为更接近语音输入法的切换式交互：

```text
Ready
  → 第一次按 Right Ctrl
  → Listening / 摄像头开启 / 开始采集
  → 第二次按 Right Ctrl，或达到 20 秒上限
  → Reading your lips / 摄像头关闭 / 最终识别
  → Copied 或 Direct input / Home 保留记录
```

- Right Ctrl 的按下事件只触发一次，忽略键盘长按产生的重复事件。
- Right Ctrl 松开不再结束录制，避免用户必须一直按住按键。
- 20 秒上限本轮保留；上限是防止失控录制和内存、磁盘占用失控的保护措施。
- 删除应用的全局 Esc 退出/取消行为，避免用户误触 Esc 导致程序退出。
- 开发阶段通过启动它的 PowerShell 窗口使用 `Ctrl+C` 终止进程；这不是最终打包应用的完整退出设计，后续需要单独设计托盘或退出入口。
- v0.3 暂不提供“取消本次录制但不识别”的快捷键；用户误触后可以让它完成一次记录，再从 Home 删除。

### 11.8 输出策略（v0.3 设计决定）

当前版本在识别成功后自动复制到系统剪贴板。这个行为会覆盖用户原本的剪贴板内容，不适合作为长期默认交互。

建议将输出拆成两种明确模式：

1. **Direct input**：优先把结果写入录制开始时锁定的输入位置；只有目标仍然有效时才执行。
2. **Clipboard only**：不自动写入其他窗口，只把结果放入剪贴板；作为显式备用模式或用户手动选择的模式。

Direct input 不能简单理解为“识别完成时把文字粘贴到当前鼠标所在位置”。识别期间用户可能切换窗口，因此必须记录目标、检查目标是否仍有效，并在失败时保留 Home 记录。直接输入需要单独做安全验收，不与模型准确率一起判断。

### 11.9 v0.3 优先级

| 优先级 | 内容 | 原因 |
| --- | --- | --- |
| P0 | Home 记录稳定保存、复制、删除、打开目录；单击开始/单击结束；20 秒上限；移除 Esc 退出 | 先解决可管理性和最核心交互，不依赖模型准确率提升 |
| P1 | 无声口型素材保存、预览、单独删除、重新识别、详情和转写版本 | 让历史记录从“文本日志”变成可复用的视觉记录 |
| P2 | Direct input、目标窗口校验、失败回退和设置页 | 风险最高，必须单独验证，不能为了模仿语音输入法而直接默认开启 |

### 11.10 v0.3 功能需求草案

| ID | 需求 | 验收方式 |
| --- | --- | --- |
| F-14 | 每次成功识别创建稳定 ID，并将文本与素材关联 | 重启应用后仍能定位同一条记录及其素材 |

### 11.11 关键风险与未决选择

- **隐私**：完整人脸视频更适合调试，但默认保存嘴部裁剪更符合本项目的公共场合场景。
- **存储**：需要显示素材占用空间，并允许用户单独删除素材；暂不自动清理，避免误删证据。
- **重识别边界**：标准化嘴部帧能复现当前模型输入，但不保证适配所有未来模型；模型和预处理版本必须写入详情。
- **删除语义**：本 PRD 暂定删除图标删除“记录 + 素材”，更多菜单中的“仅删除视觉素材”删除“素材而不删除文本”。
- **JSONL 迁移**：旧 JSONL 中没有稳定 ID，迁移时按时间、顺序和文本生成一次性 ID；迁移完成后不应重复生成记录。
