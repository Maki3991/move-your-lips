# 唇语输入法：MVP v0.3 产品需求文档

> 本文是 v0.3 的独立 Release PRD。它描述本次版本要解决的问题、用户行为、产品范围和验收标准，不替代技术设计文档，也不把尚未验证的模型能力写成产品承诺。

| 项目 | 内容 |
| --- | --- |
| 产品 | 唇语输入法（Move Your Lips） |
| 版本 | MVP v0.3 |
| 文档状态 | 需求设计稿，待开发 |
| 当前基线 | MVP v0.2：摄像头采集、唇部裁剪、模型识别、HUD 展示、剪贴板输出 |
| 文档负责人 | 产品负责人：项目发起人 |
| 目标用户 | 项目发起人本人；后续再扩展到同类用户 |
| 输入方式 | 电脑摄像头采集嘴部运动，不使用麦克风 |
| 数据策略 | 本地处理、本地保存，默认不上传云端 |
| 版本边界 | 最长单次录制 20 秒 |

## 1. 版本摘要

MVP v0.3 要把“识别一次并复制结果”推进成一个可持续使用的本地输入工具：用户可以用快捷键完成一次无声输入，结果自动进入 Home 历史；用户可以复制、删除和管理历史记录，并在需要时把识别结果直接写入当前文本输入框。

本版本的重点不是重新训练模型，也不是承诺识别准确率达到可用水平。模型准确率作为独立的技术改进工作流记录和评估；本版本先补齐输入、保存、回看和失败恢复这些产品闭环。

## 2. 要解决的问题

### 2.1 用户问题

在教室、图书馆、办公室等公共场所，用户希望快速把想法输入电脑或告诉 AI，但出声会打扰他人，也会暴露自己的谈话内容。打字速度和思考速度不一致时，用户容易丢失正在形成的想法。

### 2.2 当前版本的问题

MVP v0.2 已经可以完成一次摄像头录制到文字输出，但仍存在这些断点：

- 结果主要依赖剪贴板，历史记录的管理能力弱；
- 识别过程中的视觉素材没有形成可管理的记录；
- 用户无法区分“文字记录”和“用于重新识别的视觉素材”；
- 只能通过当前快捷键流程完成输入，尚未支持稳定的直接输入；
- 当前交互仍使用“按住开始、松开结束”的方式，长时间按键不自然；
- 删除、失败、重新识别等状态没有明确的产品行为。

### 2.3 问题证据边界

目前的用户证据主要来自项目发起人的持续使用和测试，不等于已经完成多人用户验证。因此本 PRD 只把“第一用户的真实需求”作为当前设计依据，不把它表述为全市场结论。

## 3. 目标与成功标准

### 3.1 产品目标

1. 用户可以通过一次按键开始、再次按键结束一段唇语输入。
2. 每次完成的识别都形成一条可管理的本地历史记录。
3. 用户可以在不丢失文字的情况下管理对应的视觉素材。
4. 当目标输入框可用时，识别结果可以直接写入；直接输入失败时，记录仍然保留。
5. 用户可以清楚知道当前处于录制、识别、成功、失败中的哪一个状态。

### 3.2 v0.3 成功标准

以下是功能验收指标，不是模型准确率指标：

- 连续完成 10 次符合拍摄约束的测试，应用不崩溃，至少 9 次能够生成历史记录或明确的失败记录；
- 每条成功记录都能在 Home 中复制和删除；
- 用户删除视觉素材后，文字记录仍然存在，并明确显示素材不可用；
- 用户在录制过程中再次按快捷键或达到 20 秒时，摄像头能够关闭并进入识别状态；
- 直接输入失败时，识别文字仍可在 Home 中找到，不因为窗口焦点变化而丢失；
- 全流程不调用外部大语言模型，不使用麦克风，不上传用户视频。

### 3.3 不作为本版本成功标准的指标

- 中文唇语识别达到某个固定 CER；
- 在多人、侧脸、遮挡、复杂光线下稳定工作；
- 替代系统级输入法；
- 让用户在任何应用、任何控件中都能无条件注入文字。

## 4. 用户与使用场景

### 4.1 第一用户

项目发起人本人：重度使用语音输入与 AI 沟通，能够在电脑前保持正面拍摄，但在公共场合不方便出声。

### 4.2 核心场景

- 教室中，用户需要快速向 AI 输入想法，但不方便说话；
- 图书馆中，用户需要保持安静；
- 办公室中，用户不希望让旁人听到正在输入的内容；
- 用户坐在电脑前，摄像头可以拍到单人正脸和嘴部。

### 4.3 当前拍摄约束

- 画面中默认只有一名用户；
- 用户正对摄像头；
- 嘴部没有被口罩、手或其他物体遮挡；
- 光线基本稳定；
- 单次输入不超过 20 秒；
- 第一版不处理多人画面、地铁等拥挤环境和复杂背景。

## 5. 版本范围

### 5.1 本版本包含

#### P0：必须完成

- Home 历史记录的稳定保存和加载；
- 历史记录的复制、删除、打开本地存储目录；
- Home 自动刷新，以及 `Ctrl+R` 手动刷新；
- Right Ctrl 改为“按一次开始、再按一次结束”；
- 20 秒最长录制限制；
- 移除 Esc 作为退出或取消快捷键；开发过程中使用终端 `Ctrl+C` 终止进程；
- 明确的录制、识别、成功和失败状态；
- 识别失败时保留失败记录或错误信息，不生成空的成功记录。

#### P1：本版本优先完成

- 为每次识别保存可选的嘴部视觉素材；
- Home 记录卡片的 More 菜单；
- 播放嘴部视觉素材；
- 基于保存的标准化嘴部素材重新识别；
- 查看记录详情和识别版本；
- 只删除视觉素材但保留文字记录；
- 直接把识别结果写入用户开始录制时锁定的文本输入框。

#### P2：后续版本

- 模型切换和模型效果对比；
- 个体化微调或校准流程；
- 更长输入和可配置时长；
- 多人、侧脸和复杂背景；
- 系统级输入法注册、安装包和开机自启；
- 云端同步、跨设备历史和团队协作。

### 5.2 本版本不包含

- 音频录制、音频播放或音视频融合；
- 外部 LLM 对识别文本进行改写、总结或补全；
- 自动修正模型原始结果并伪装成唇语模型输出；
- 在没有目标输入框时强行把文字粘贴到当前窗口；
- 保存完整人脸视频作为默认素材；
- 通过本版本宣称“已经解决中文唇语识别准确率”。

## 6. 用户流程

### 6.1 启动流程

```text
启动应用
  → 显示 Home
  → 摄像头保持关闭
  → 后台加载模型
  → 显示 READY 或明确的加载失败状态
```

启动时不弹出大摄像头窗口，也不要求用户先完成一套尚未实现的个性化训练。

### 6.2 一次输入流程

```text
READY
  → 用户按一次 Right Ctrl
  → 打开摄像头，检测并追踪嘴部
  → 显示 LISTENING 和嘴部画面
  → 用户无声做出说话动作
  → 用户再次按 Right Ctrl，或达到 20 秒
  → 关闭摄像头
  → 显示 READING YOUR LIPS
  → 完成最终识别
  → 保存记录
  → 直接输入成功，或显示 COPIED / 可在 Home 中复制
```

快捷键只响应按键动作，不再使用“松开按键结束”。一次录制最多持续 20 秒；键盘抬起不改变录制状态。

### 6.3 Home 历史流程

```text
打开 Home
  → 查看按时间倒序排列的识别记录
  → 鼠标移入记录卡片
  → 显示 Copy、Delete、More
  → 用户执行操作
  → 页面立即更新，并保留明确的成功或失败提示
```

Home 不放置占据主要空间的大型 Refresh 按钮。新记录默认自动出现；用户也可以按 `Ctrl+R` 刷新。

| FR-02 | P0 | Home 展示历史 | 应用重启后仍能按时间倒序展示本地记录 |

| FR-17 | P1 | 直接输入 | 若录制开始时存在受支持的文本输入框，识别成功后将结果写入该输入框 |

| FR-19 | P1 | 不默认覆盖剪贴板 | 直接输入成功时不改变用户原有剪贴板；用户点击 Copy 后才主动复制 |
| FR-20 | P1 | 识别失败可追踪 | 失败记录包含错误类型和阶段，例如摄像头、检测、帧数、模型或目标输入框失败 |

## 8. Home 页面要求

### 8.1 记录卡片

每条记录至少展示：

- 识别时间；
- 识别文本；
- 处理时长和帧数；
- 识别状态；
- 视觉素材是否存在；
- 识别版本或模型名称。

Home 展示完整文字；录制 HUD 和 COPIED 提示只展示一行，过长文本使用省略号，不改变实际保存的文本。

### 8.2 卡片操作

鼠标移入卡片后显示三个操作：

1. **Copy**：复制当前文字；
2. **Delete**：删除记录，默认同时删除关联视觉素材；
3. **More**：展开播放素材、重新识别、查看详情、删除素材。

“删除记录”和“删除素材”必须是两个不同操作，避免用户误以为删除视频会删除文字。

### 8.3 视觉状态

- 有文字、有素材：显示可复制、可播放、可重新识别；
- 有文字、素材已删除：保留文字，标记“素材不可用”；
- 识别失败：保留失败记录和错误原因，不显示为成功结果；
- 重新识别后：原结果不被静默覆盖，界面可以查看当前版本和历史版本。

## 9. 本地数据与存储

### 9.1 当前实现

当前 v0.2 主要使用 `outputs/mvp/recognitions.jsonl` 保存识别记录。它适合实验记录和追加写入，但不适合长期支持删除、版本、素材关系和详情查询。

### 9.2 v0.3 目标结构

```text
outputs/mvp/
├── records.sqlite3                 # 记录、版本和素材元数据
├── records/
│   └── <record-id>/
│       ├── record.json              # 可读的单条记录快照
│       ├── mouth.mp4                # 可选：嘴部预览素材
│       └── input.npz                # 可选：模型标准化输入，用于重新识别
├── recognitions.jsonl               # 迁移期兼容文件
└── hud_setup_complete.json
```

数据库用于管理关系和状态，文件夹用于保存较大的视觉素材。最终实现可以选择等价的数据层，但必须满足以下产品行为：

- 文字记录和视觉素材可以分别存在、分别删除；
- 记录可以关联多个识别版本；
- 应用重启后不依赖内存恢复历史；
- 识别素材默认只包含嘴部及少量周边，不保存完整摄像头画面；
- 不采集、不保存麦克风音频；
- 用户可以从 Home 打开实际存储目录。

### 9.3 存储生命周期

- 单次录制最多 20 秒，避免第一版产生无限增长的素材；
- 默认保存嘴部素材，而不是完整人脸视频；
- 删除整条记录时删除关联素材；
- 只删除素材时保留文字和元数据；
- 后续再增加存储占用统计、批量删除和容量上限。

## 10. 直接输入要求

直接输入不是“识别后无条件粘贴到当前窗口”。产品必须先确定输入目标：

1. 用户在目标文本框中放置光标；
2. 用户第一次按 Right Ctrl 时记录当前受支持的输入目标；
3. 用户第二次按 Right Ctrl 结束；
4. 识别完成后，只有目标仍然有效且控件受支持时才写入；
5. 目标失效时，不向当前活动窗口盲目粘贴；
6. 识别结果继续保存到 Home，用户可以手动 Copy。

剪贴板不是默认的中转结果。若底层实现暂时必须借助剪贴板完成输入，必须在操作后恢复用户原有剪贴板内容；用户主动点击 Copy 时才覆盖剪贴板。

## 11. 失败与边界状态

| 场景 | 产品行为 |
| --- | --- |
| 摄像头权限不足 | 显示检查 Windows 摄像头权限的提示，不崩溃 |
| 没检测到人脸或嘴部 | 保持录制状态并提示调整位置；结束后记录失败原因 |
| 帧数不足 | 不生成空的成功文本，显示“录制太短” |
| 20 秒自动结束 | 进入识别，并说明由时长上限触发 |
| 模型推理失败 | 保存失败阶段和错误信息 |
| 目标输入框消失 | 不注入其他窗口，保留 Home 记录 |
| 视觉素材已删除 | 文字可复制，播放和重新识别显示不可用 |
| 应用被 Ctrl+C 终止 | 释放摄像头；已完成的历史记录不回滚 |

## 12. 隐私与安全

- 默认所有识别在本机完成；
- 不使用麦克风，不保存音频；
- 默认不保存完整人脸视频；
- Home 和本地素材目录不对外同步；
- 删除素材后，不再承诺可以重新识别；
- 直接输入必须防止向错误窗口写入用户内容；
- 日志中不记录不必要的完整视频帧或敏感文本副本。

## 13. 技术约束与依赖

本 PRD 不规定具体代码结构，但当前实现受到以下条件约束：

- Windows 桌面环境；
- 电脑摄像头；
- 现有中文视觉语音识别模型和嘴部预处理链路；
- 主要使用 CPU 推理，识别延迟可能达到数秒；
- 模型输入需要固定帧率和标准化嘴部画面；
- 直接输入需要可靠的 Windows 全局快捷键和窗口/控件识别能力。

模型切换、个体化微调和准确率优化应记录在单独的模型评测文档中，不应把技术实验结果直接写成 v0.3 的用户承诺。

## 14. 未决问题

以下问题在开发前需要明确，不应由程序员在实现时自行猜测：

1. v0.3 的直接输入先支持普通 Windows 文本框，还是同时支持浏览器、VS Code 和聊天应用；
2. 嘴部预览视频和模型标准化帧是否同时保存，还是只保存一种；
3. 重新识别版本是否需要允许用户选择模型；
4. 是否需要提供“永不保存视觉素材”的隐私设置；
5. 识别结果是否允许用户在 Home 内编辑，还是只允许复制；
6. 20 秒上限何时根据真实使用数据调整。
